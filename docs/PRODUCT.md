# 云端支线任务：有证据的技术研究助手

开发目标是交付可独立使用的 Agent 工程技术研究产品，接续教程的研究需求、工具评测和上线验收三节毕业课。

## 首个交付范围

1. 将固定五篇演示资料升级为版本化资料库。维护者可管理允许来源的公开资料，记录标题、来源 URL、获取/录入时间、内容哈希、版本与来源类别；如使用手工录入内容必须明确标识，合成冲突材料继续标为练习。
2. 实现研究任务状态及可恢复的 run_id，保存问题、实际读取的资料版本、引用摘录、操作摘要、已知用量与失败状态。取消、失败、无证据和冲突应明确显示。
3. 在独立云端开发环境用 SQLite 先完成迁移、持久化与重启恢复，提供报告列表、详情、删除自己的记录及 Markdown / JSON 导出；持久化数据和上传原文不可进 Git。公开部署前解决身份与隔离，不能公开共享私人报告或无保护地写入资料库。
4. 保留 DeepSeek 的 OpenAI 兼容消息和工具调用格式；服务端 DEEPSEEK_API_KEY / DEEPSEEK_MODEL（骨架默认 deepseek-flash），固定官方 endpoint。无密钥继续 demo 与 mock。保留实际已读引用校验、三轮/两工具/输出/超时预算及访问控制；不展示内部推理。
5. 实现可重复评测，至少覆盖证据充分、证据不足、来源冲突，以及伪造/未读引用、资料更新、非法工具、取消和上游故障。结构校验与人工语义核验分别记录，不能把引用存在当作语义正确。
6. 完成 React 到 API 的真实演示链路、移动端与键盘操作、错误恢复、下载和持久化验收；补充冻结依赖 CI、运行文档与 Vercel 发布配置。

## 边界与后续

- 第一轮优先不需要额外账号或费用的能力。若增加网络抓取，必须采用固定白名单、有界响应与重定向策略、内网地址拒绝；不开放任意网页或文件系统工具。执行用户代码仅限隔离沙箱。
- SQLite 仅用于支持持久卷的开发/运行环境；Vercel 的临时文件不能被宣称为可靠生产存储。用清晰存储接口准备托管数据库，所需授权列入人工清单，不因缺少凭据停掉其他工作。
- 当前任务授权开发此独立公开 GitHub 仓库并持续提交/推送。main 稳定、develop 开发，中文 feat/fix/docs/test/chore 前缀；普通推送，禁止强推 main。提交前运行 scripts/check_secrets.py，扫描暂存区、工作区与 ZIP。
- 不索取聊天中的密钥，不读取或输出认证状态，不使用重置卡，不购买额度，不进行未经费用授权的真实模型调用。
- 已有唯一人工配置对话为“Deep AI Station｜一次性人工配置”（01a10121-db57-71e3-bcc2-7f09e96dc54b）。云端若无法访问该对话，交付一份合并的 HUMAN_ACTIONS 文档供主线转交；不要重复开多个人工任务。
- 用户控制优先。云端自动测试用 headless；如环境没有 Codex 内置 Browser，只明确记录待主线完成的原生验收，不虚构成功或远控用户桌面。
